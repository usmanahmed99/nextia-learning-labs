## Version: pull date and query

Pulled on 2026-10-07 from the Socrata (SODA) API, `https://data.cityofnewyork.us/resource/erm2-nwe9.csv`, with:

- `$select` = `unique_key, created_date, closed_date, agency, complaint_type, descriptor, location_type, incident_zip, address_type, city, status, due_date, resolution_description, resolution_action_updated_date, community_board, council_district, borough, open_data_channel_type, latitude, longitude`
- `$where` = `agency='DOT' AND created_date >= '2024-01-01T00:00:00' AND created_date < '2025-07-01T00:00:00'`
- `$order` = `unique_key`, pages of 50,000 (`$limit`, `$offset`)

`get_data.py --fresh` in the case-study project runs this query. A fresh pull on 2026-10-07 (2 min 22 s) returned the same 315,424 rows with values identical to the frozen file. The city updates the dataset every day, so later pulls can differ (closing times, statuses, texts).

## Changes made

- 20 of the source's 44 columns selected (the query above). Left out: the street-address columns (`incident_address`, `street_name`, `cross_street_1/2`, `intersection_street_1/2`, `landmark`), `bbl`, `x/y_coordinate_state_plane`, `location`, `police_precinct`, `descriptor_2`, the park, vehicle, taxi and bridge columns, `agency_name`, `facility_type`, and the portal's computed region columns.
- Values unchanged. The API's CSV was read as text (`pandas.read_csv(dtype=str, keep_default_na=False, na_values=[""])`) and written again with `to_csv(index=False)`, which quotes only the values that need it, compressed with gzip (`mtime=0`).

## Columns used

| Column | Meaning (from the portal) | Written |
|---|---|---|
| `unique_key` | Unique identifier of a service request | at creation |
| `created_date` | Date the request was created; `YYYY-MM-DDTHH:MM:SS.000`, New York local time | at creation |
| `closed_date` | Date the request was closed by the responding agency | later |
| `agency` | Responding agency (always `DOT` here) | at creation |
| `complaint_type`, `descriptor` | The problem and its detail (33 and 288 values) | at creation |
| `location_type`, `incident_zip`, `address_type`, `city`, `community_board`, `council_district`, `borough`, `latitude`, `longitude` | Where the problem is (many come from geovalidation) | at creation |
| `open_data_channel_type` | How the request reached 311: `ONLINE`, `PHONE`, `MOBILE`, `OTHER`, `UNKNOWN` | at creation |
| `status` | Status of the request, on the pull date | later |
| `due_date` | Always empty in this selection | — |
| `resolution_description` | The last action taken by the agency; "may describe next or future steps" | later |
| `resolution_action_updated_date` | Date the agency last updated the request | later |

## Known traps (measured on the frozen file)

| Trap | Count | How the case study handles it |
|---|---|---|
| Repeated submissions: rows equal in all columns except `unique_key` | 273 groups, 665 rows, 392 extra | removed, keep the lowest key |
| Closed before created | 1,482 (1,458 street lights; status mostly `Pending`) | quarantined |
| Closed in the same second as created | 11,162 (about half marked as duplicates) | kept; on time |
| Open more than 365 days | 1,445 | kept; late |
| Still open (no `closed_date`) | 6,083 | kept; late if 14 days have passed |
| Status disagrees with `closed_date` | 508 `Assigned` and 9 `Pending` with a closing time; 1 `Closed` without | `closed_date` decides |
| No coordinates | 46,841 (14.9%): 29% of street conditions, nearly all highway requests | `has_location` = 0; history feature missing |
| `borough` = `Unspecified` | 1,728 | NULL / `unknown` |
| `community_board` with `Unspecified` | 22,003 | NULL |
| `open_data_channel_type` = `UNKNOWN` | 182,215 (57.8%) | NULL / `unknown`; a real category (late 10.8% vs 25.9% for `MOBILE`) |
| `incident_zip` not five digits | 1 (`NA`) | NULL |
| Batch times: `created_date` at exactly 07:00:00 / 22:10:00 | 1,908 / 751 (next most common time: 278) | flag `batch_time` |
| Mis-encoded text: UTF-8 read as Latin-1 in `resolution_description` (`Transportationâ\x80\x99s`) | 96,528 rows (3 distinct texts) | repaired with `encode("latin-1").decode("utf-8")` |
| Leaky columns for a model at creation time | `status`, `closed_date`, `resolution_description`, `resolution_action_updated_date` | never features |

The checks are `queries/01` to `12` in the case-study project and `reference/c04/case-studies/cs02_repairs.py`.
